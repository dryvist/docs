## The tools landscape

| Layer | Repo / tool | What it owns |
| --- | --- | --- |
| **Universal config** | [Assistant rules](/ai-development/ai-assistant-instructions) | `CLAUDE.md`, `AGENTS.md`, rules, permissions, workflows: read by every AI tool |
| **Cloud models** | Claude Code, Antigravity (`agy`), GitHub Copilot | The IDEs and CLIs that do the work |
| **Local inference** | MLX | Apple Silicon-native model inference for typo fixes, quick edits, no cloud tokens |
| **Extensions** | [Claude Code plugins](/ai-development/claude-code-plugins), `claude-code-routines`, `ai-workflows`, `raycast-smart-issue` | Commands, scheduled agents, Copilot workflows, Raycast UI on top of MLX |

## Model routing

Each model has a sweet spot, and work is routed to the cheapest one that can
actually do it. Deep reasoning and multi-file refactors go to the strongest
model. Line-level completions go to the cheap high-volume one, and anything
trivial goes to local inference rather than burning cloud tokens.

[Model routing](/ai-development/model-routing) covers how that choice is
made and governed. One endpoint sits in front of every backend, and callers ask
for a role instead of a model name. It also covers the difference between a
spend control that is enforced and one that is merely advised.

Routing rules live in `~/CLAUDE.md` and `AGENTS.md`, sourced from
[ai-assistant-instructions](https://github.com/JacobPEvans/ai-assistant-instructions). See [Repo
boundaries](/ai-development/repo-boundaries) for how rules, plugins, and docs are split across
three repositories.
