Event in (`issues.opened`, `pull_request`). PR out. Jobs use GitHub-hosted or RunsOn runners and the AI-bot App identity.

GitHub Actions handle the event-driven side of automation. Something happens in GitHub:
an issue is filed or a PR is opened. The reusable workflows in
[`JacobPEvans/.github-ai`](/automation/repos/ai-workflows) react. The result lands as a
ready PR labeled `human:review`, signed by
[`JacobPEvans-claude[bot]`](/infrastructure/cicd/git-signing) and ready for review.

The cron-driven sibling (work that runs on a schedule rather than in response to an event) is documented under [Scheduled routines](/automation/scheduled-routines/overview).

## How they fit

| Trigger | Reusable workflow | Outcome |
| --- | --- | --- |
| `issues.opened` (label: `agentic-implement`) | `issue-resolver.yml` | Ready PR labeled `human:review` implementing the issue |
| `pull_request` opened or `synchronize` | `code-simplifier.yml` | Review comments when ready |

CI failure repair and cutover status live in CI resolver.
