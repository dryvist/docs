> One repo of reusable workflows. Consumer repos write thin callers, choose Claude or Codex once, and receive workflow updates through reviewed pull requests.

[`JacobPEvans/.github-ai`](https://github.com/JacobPEvans/.github-ai) ships reusable GitHub Actions workflows (`on: workflow_call:`). The workflow
orchestration, provider routing, and rate guards live there. Prompt text comes from the pinned
[Prompt catalog](/automation/repos/ai-llm-prompts). Consumers declare triggers and permissions.

## Event-triggered workflows

These run on GitHub events. Wire one caller per workflow you want.

| Workflow | Trigger | What it does |
| --- | --- | --- |
| `issue-triage.yml` | `issues: [opened]` | Categorizes, deduplicates, labels new issues |
| `issue-resolver.yml` | `issues: [opened]` | Creates a ready PR labeled `human:review` when the issue is well-scoped and not excluded by labels |
| `project-router.yml` | `issues/pull_request: [opened, labeled]` | Routes items to GitHub Projects with smart field assignment |
| `post-merge-docs-review.yml` | `push: [main]` → dispatch | After merge, audits docs touched by the commit, creates fix PRs |
| `post-merge-tests.yml` | `push: [main]` → dispatch | After merge, analyzes the code changes and drafts targeted tests |
| `issue-linker.yml` | `pull_request: [opened, closed]` | Links open issues to PRs on open; closes resolved issues on merge |
| `notify-ai-pr.yml` | `pull_request: [opened]` from a bot | Slack notification when an AI-authored PR opens |

CI repair workflows and their cutover status live in CI resolver.

## Scheduled workflows

These run on cron, typically called with `schedule:` and a manual `workflow_dispatch:`.

| Workflow | Default schedule | What it does |
| --- | --- | --- |
| `code-simplifier.yml` | Daily 04:00 UTC | DRY enforcement, dead code removal, opens ready PRs |
| `best-practices.yml` | Weekly Wed 03:00 UTC | Audit creating actionable recommendations |
| `next-steps.yml` | Daily 05:00 UTC | Analyzes merge momentum, suggests next logical action |
| `issue-sweeper.yml` | Weekly Mon 06:00 UTC | Scans open issues, comments on progress, closes resolved |
| `issue-hygiene.yml` | Weekly Mon 07:00 UTC | Detects duplicates, links merged PRs, flags stale issues |
| `repo-orchestrator.yml` | `workflow_dispatch` | Multi-repo hub-and-spoke dispatcher for ad-hoc operations |

## How a reusable caller looks

A reusable-workflow caller is the smallest YAML that declares a trigger, sets permissions, and forwards to the upstream:

```yaml
name: Issue Triage
on:
  issues:
    types: [opened]
permissions:
  contents: read
  id-token: write
  issues: write
jobs:
  run:
    uses: JacobPEvans/.github-ai/.github/workflows/issue-triage.yml@v1
    secrets: inherit
```

Permission shape varies per workflow. `issue-resolver` needs `pull-requests: write`, and
`post-merge-*` needs `actions: write` for the re-dispatch. The [canonical caller
templates](https://github.com/JacobPEvans/.github-ai/blob/main/docs/GETTING_STARTED.md) list the exact
permission block for each.

## How prompts are loaded

The reusable workflows check out the catalog at its pinned release commit and select an asset from `automation/`.
They remove its OKF frontmatter before passing the prompt to the selected model. Local workflow YAML still owns
triggers, permissions, publishing, and provider configuration.

## Authentication

The `GH_ACTION_AI_AGENT=claude|codex` variable selects the agent for reusable
`.yml` workflows. Its default is `claude`, so existing callers keep that
behavior. Set it to `codex` at the organization, repository, or environment
level to switch every inherited workflow.

| Name | Kind | Purpose |
| --- | --- | --- |
| `GH_ACTION_AI_AGENT` | Variable | `claude` or `codex`. Defaults to `claude`. |
| `GH_ACTION_AI_API_KEY` | Secret | Anthropic API key used when the selector is `claude`. |
| `OPENAI_API_KEY` | Secret | OpenAI API key used when the selector is `codex`. |
| `GH_ACTION_AI_BASE_URL` | Variable | Optional Claude-compatible endpoint. Leave empty for direct Anthropic. |
| `GH_ACTION_AI_MODEL` | Variable | Optional global Claude model default. |
| `GH_ACTION_AI_MODEL_CODE` | Variable | Optional Claude code tier. Falls back to `GH_ACTION_AI_MODEL`. |
| `GH_ACTION_AI_MODEL_ISSUES` | Variable | Optional Claude issue tier. Falls back to `GH_ACTION_AI_MODEL`. |
| `GH_ACTION_AI_MODEL_PLAN` | Variable | Optional Claude planning tier. Falls back to `GH_ACTION_AI_MODEL`. |
| `GH_ACTION_AI_CODEX_RESPONSES_API_ENDPOINT` | Variable | Optional Codex Responses API endpoint. |
| `GH_ACTION_AI_CODEX_MODEL` | Variable | Optional Codex model override. |
| `GH_ACTION_AI_CODEX_EFFORT` | Variable | Optional Codex reasoning-effort override. |
| `GH_ACTION_AI_CODEX_VERSION` | Variable | Optional Codex command-line tool version override. |

> **OAuth tokens are prohibited in unattended CI.** A Claude Code subscription token
> (`CLAUDE_CODE_OAUTH_TOKEN`) in GitHub Actions violates the
> [Claude Code Terms of Service](https://www.anthropic.com/legal/terms).
> It can lead to an account ban. Reserve subscription tokens for interactive
> sessions. Use the standard `GH_ACTION_AI_API_KEY` for programmatic access.

GitHub Agentic Workflows are retired. One dormant reference template remains in
the catalog. No active repository compiles or runs GH-AW Markdown.
Provider details and model configuration live in [AUTHENTICATION.md](https://github.com/JacobPEvans/.github-ai/blob/main/docs/AUTHENTICATION.md).

## Security boundary

- Model job gets no privileged GitHub App token.
- Checkout stores no credentials.
- It returns structured output or workspace changes.
- Publisher validates and performs GitHub writes.

Repository comments, labels, branches, commits, and pull requests stay
deterministic. Both agents share this boundary. Changing the selector does not
change GitHub permissions.
