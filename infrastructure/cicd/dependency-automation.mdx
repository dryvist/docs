## Scanner coverage

Renovate keeps first-party shared workflow references on the floating `@v1` major tag.

| Pin shape | Mechanism |
| --- | --- |
| Container image pins in role defaults | [Shared image manager](#container-image-pins) |
| Annotated version pins | Shared custom managers for supported Ansible, Nix, Packer, shell, `.env.example`, and workflow files |
| Version embedded in a URL | Bespoke manager; the annotation manager would capture the whole URL |
| Commit SHA inside a flake URL | Bespoke manager tracking it as a git ref |
| Actions, collections, and lockfiles | Built-in managers |

The shared custom managers use a `# renovate:` comment to track annotated
version pins in supported files. These include Ansible defaults, vars, tasks,
templates, inventory, group vars, host vars, playbooks, and scripts; Nix and
Packer files; shell files; `.env.example`; and GitHub workflow YAML.

```yaml
# renovate: datasource=<ds> depName=<name> [versioning=<v>]
some_component_version: "1.2.3"
```

Place the annotation immediately before the value it tracks. The annotation
can set a `versioning` value; otherwise the manager uses `semver-coerced`.
Date-shaped or ragged tags need `loose` versioning.

The image manager covers both `defaults/main.yml` and `defaults/main/` layouts.
A self-test checks those paths against the shared preset.

Some pins have a companion checksum the scanner cannot calculate. Use an
update-branch fixer to recalculate it and a pull-request gate to reject a
version/hash mismatch. The fixer alone cannot enforce the relationship.
Test the gate with a deliberate mismatch and confirm that it fails.

The shared preset disables the Dependency Dashboard. When changing a manager,
use the [coverage self-test](https://github.com/JacobPEvans/.github/blob/main/nix/renovate-manager-coverage-selftest.nix)
to check both role-default layouts. Extend the scanner for any new file shape
and add a pull-request gate for companion hashes or coupled versions.
Hindsight has coupled client and server pins.
Proxmox guest tags use validation
rather than schema enforcement.

## Master and repo config

[JacobPEvans/.github](https://github.com/JacobPEvans/.github) is the Renovate policy master. Its
[`renovate-presets.json`](https://github.com/JacobPEvans/.github/blob/main/renovate-presets.json)
owns the shared policy. The `github>JacobPEvans/.github` entry point is defined in
[`default.json`](https://github.com/JacobPEvans/.github/blob/main/default.json), and
[`renovate-nix.json`](https://github.com/JacobPEvans/.github/blob/main/renovate-nix.json) adds Nix
support.

[`dryvist/.github`'s `default.json`](https://github.com/dryvist/.github/blob/main/default.json)
keeps the `local>dryvist/.github` and `github>dryvist/.github` entry points. It combines
`config:recommended` with the master preset. Its
[`renovate-presets.json`](https://github.com/dryvist/.github/blob/main/renovate-presets.json)
re-exports the JacobPEvans master preset unchanged; dryvist/.github owns no separate policy.
Consumer configs extend the shared preset, then list only repo-specific holds.

## Schedule and grouping

The shared schedule is Saturday 00:00–05:59 in
`America/Indiana/Indianapolis`. Renovate's built-in `group:all` opens one PR
per repository, with majors included.

| Update | Release-age hold | Merge policy |
| --- | --- | --- |
| Minor, patch, digest, and pin updates | 7 days | Auto-merge after required checks pass |
| Other major updates | 30 days | Auto-merge after required checks pass |
| First-party updates, including majors | 0 days | Auto-merge after required checks pass |
| Trusted-organization majors | 7 days | Auto-merge after checks; `dep:review` adds dependency review |
| Vulnerability alerts | 1 day | Auto-merge after required checks pass; alerts may open at any time |

The complete trust tiers live in
[`SECURITY.md`](https://github.com/JacobPEvans/.github/blob/main/SECURITY.md#dependency-trust).

## Nix flake locks

Nix repos also extend the shared [`renovate-nix` preset](https://github.com/JacobPEvans/.github/blob/main/renovate-nix.json).
Renovate's `nix` manager and `lockFileMaintenance` relock `flake.lock` in the Saturday window.
For `lockFileMaintenance`, Renovate sets `minimumReleaseAge` to `null` because it delegates version
selection to the package manager. That manager's own release-age setting controls which versions
enter the lockfile.

## Package-manager release ages

Project-level package managers use native settings for a seven-day release age:

- **uv in `nix-ai` orchestrator.** Set `exclude-newer = "7 days"` and
  `required-version = ">=0.9.17"` in
  [`orchestrator/pyproject.toml`](https://github.com/dryvist/nix-ai/blob/develop/orchestrator/pyproject.toml).
- **Bun in `ai-workflows-testing`.** Set `minimumReleaseAge = 604800` seconds in
  [`bunfig.toml`](https://github.com/dryvist/ai-workflows-testing/blob/main/bunfig.toml).
- **pnpm in three projects.** Set `minimumReleaseAge: 10080` minutes in each project's
  `tests/pnpm-workspace.yaml`:
  - [`cc-edge-pack-template`](https://github.com/dryvist/cc-edge-pack-template/blob/main/tests/pnpm-workspace.yaml)
  - [`cc-edge-codex-io`](https://github.com/dryvist/cc-edge-codex-io/blob/main/tests/pnpm-workspace.yaml)
  - [`cc-stream-openrouter-rest-io`](https://github.com/dryvist/cc-stream-openrouter-rest-io/blob/main/tests/pnpm-workspace.yaml)

The
[`nix-home` Home Manager package config](https://github.com/dryvist/nix-home/blob/develop/modules/home-manager/npm/config.nix)
also writes user-level settings:

- npm's `.npmrc` sets `min-release-age=7`.
- Bun's `~/.bunfig.toml` and `~/.config/.bunfig.toml` set `minimumReleaseAge = 604800` seconds.
- uv's `~/.config/uv/uv.toml` sets `exclude-newer = "7 days"`.
- pip's `~/.config/pip/pip.conf` sets `uploaded-prior-to = P7D`.

## Container image pins

One shared custom manager tracks `*_image:` keys in Ansible role defaults. It accepts quoted,
unquoted, and folded values, with an optional `sha256` digest. Use concrete tags, not `latest` or
`stable`.


## Dependabot security updates

Dependabot security updates are off, so Renovate is the only source of security PRs. Dependabot alerts stay on, and
Renovate reads them.
