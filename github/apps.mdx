Every GitHub App in the estate inherits the [shared settings](#shared-settings) on this
page. Each App also has its own page, listed under [Apps](#apps). That page is the App's
**Homepage URL**, `https://docs.jacobpevans.com/github/apps/<app-slug>`. It holds the App's
IDs and only the settings it overrides. Any other page that needs an App setting links to
these pages. It never copies a value.

## Shared settings

The table follows the order of GitHub's "Create GitHub App" form.

| Field | Shared value |
| --- | --- |
| Owner | The GitHub Enterprise account |
| GitHub App name | `<owner>-<role>`, for example `JacobPEvans-claude-admin` |
| Description | One sentence naming what the App is for |
| Homepage URL | `https://docs.jacobpevans.com/github/apps/<app-slug>`, the App's own page |
| Callback URL (redirect URI) | None; wildcard matching off |
| Expire user authorization tokens | On |
| Request user authorization (OAuth) during installation | Off |
| Enable Device Flow | Off |
| Setup URL, Redirect on update | None, off |
| Webhook: Active | Off. An App only mints installation tokens; it receives no events. |
| Permissions | None by default. Each App sets its own least-privilege list. |
| Subscribe to events | None |
| Where can this GitHub App be installed | Only on this account, meaning the organizations of the Enterprise |
| Installation | Every organization, selected repositories, managed by [JacobPEvans-claude-admin](/github/apps/jacobpevans-claude-admin) |
| Private key | One active key. To rotate, add the new key, switch consumers, then delete the old one. |

Each installation lists its repositories explicitly. The Enterprise API lets claude-admin add a new repository, so
nobody toggles access in the UI. Minted tokens stay short-lived and scoped to one repository.

## Installing in each organization

The Enterprise owns the App definition, so one edit changes it for every organization.
Each organization still needs its own installation.

- An Enterprise-owned App installs on the Enterprise or on organizations inside it. It
  cannot install on a personal account.
- Only an App installed on the Enterprise itself can edit an installation's repositories, through the
  [Enterprise organization-installations API](https://docs.github.com/en/enterprise-cloud@latest/rest/enterprise-admin/organization-installations).
  That is why claude-admin is installed there.
- A permission change made by an Enterprise owner is accepted automatically in every
  organization. A change made by an App manager waits for an organization owner.
- An App manager can edit settings and keys but cannot install the App.

GitHub documents the rules in
[Creating GitHub Apps for your enterprise](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-github-apps-for-your-enterprise/creating-github-apps-for-your-enterprise).

## Apps

Each App's page holds its App ID, client ID, and overrides. **Permissions** is always an
override: each App sets its own least-privilege list, and GitHub's App settings page holds
the live list.

| App | Purpose |
| --- | --- |
| [`jacobpevans-claude`](/github/apps/jacobpevans-claude) | Trusted command-line agents |
| [`openbao-service-broker`](/github/apps/openbao-service-broker) | Administrator gates, runners, and the docs publisher |
| [`jacobpevans-release-please`](/github/apps/jacobpevans-release-please) | Release automation |
| [`jacobs-agent-smith`](/github/apps/jacobs-agent-smith) | Untrusted job execution in a sandbox |
| [`jacobs-hermes-agent`](/github/apps/jacobs-hermes-agent) | The Hermes review agent |
| [`JacobPEvans-claude-admin`](/github/apps/jacobpevans-claude-admin) | Enterprise and organization administration |

<Note>
**Identifiers are public**

An App ID and client ID are identifiers, not secrets. The private key, client secret, and
webhook secret are never written in these docs.
</Note>
