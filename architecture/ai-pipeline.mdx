The goal: file a GitHub Issue, grab coffee, come back to a PR that's been implemented, tested, and
reviewed by multiple AI models. All that's left is a thumbs up. Not fully there yet, but close enough
to be dangerous.

Humans decide *what* to build. AI agents handle the *how*. Automation runs the boring parts. A human
gives the final sign-off. Claude, Antigravity, Copilot, and local MLX models each do what they're
best at. The right model gets the right job, instead of throwing everything at one.

## The model-routing philosophy

The routing is opinionated, not magic. Every model has a sweet spot, and clear
rules in `~/CLAUDE.md` and `AGENTS.md` say *which* model to use *when*. The
strongest model handles multi-file refactors and deep reasoning. The cheap one
handles line-level completion. Local inference covers anything not worth cloud
tokens.

The reasoning behind that split, and how it is governed once several agents share
one endpoint, lives on [Model routing](/ai-development/model-routing). The serving
stack that runs the local tiers is under [Local LLM](/local-llm/overview).

## Local AI gateway (LiteLLM)

The [LiteLLM router pool](/local-llm/homelab-gpu) is the single endpoint for the shared local
inference fabric on the homelab. Workstation AI tools reach cloud providers (OpenAI, Gemini,
OpenRouter) directly, using each tool's own native credentials. The router pool isn't in that path.

Tools resolve task classes (Research, Coding, Review, Pre-commit) to a current model at call time.
Never hardcode model identifiers in committed config. When `localOnlyMode` is enabled, every request
routes exclusively to the local MLX inference server.

See [Homelab GPU](/local-llm/homelab-gpu) for routing conventions, local-only mode details, and provider capabilities.

### Priority order

1. **Anthropic official**: Claude Code plugins, skills, patterns
2. **LiteLLM router**: local, on-estate inference routing across the router pool
3. **Personal or custom**: only when no alternative exists

## Observability layer

Every interaction in this pipeline emits OpenTelemetry. Cribl Edge and Stream route logs and
supported metrics to Splunk. Cribl routes traces to Langfuse and [Phoenix](/observability/phoenix)
(merged in git, not yet deployed); Splunk receives no traces. [Purpose-built Splunk apps](/observability/overview) visualize the
logs and metrics. If an AI agent touched code, there's a trace.
