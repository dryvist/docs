Vikunja tracks task work. Incidents go to Zammad. Every task follows the
agent contract.

## How it works

Vikunja has no epic or sprint object. Parent-task relations form epics. A
one-week date range forms a cycle.

~~~mermaid
flowchart LR
  C[Caller] --> K[Vikunja clerk]
  K --> I[Inbox project]
  I --> T[Triage agent]
  T --> D[Domain project]
  D --> S[One session per task]
  S --> E[Evidence comment]
~~~

## Tracker conventions

| # | Rule | Convention |
| --- | --- | --- |
| 1 | One task is one AI session. | One agent, one context, one verified change (usually one pull request), and one done-check. Work that cannot finish in one session is an epic split before work starts. |
| 2 | A task body is a brief. | State the goal, repository and paths, done-check command and expected result, and links. A delegate can use the body as written. If a task lacks these facts, add needs-info and ask one question. |
| 3 | Epic. | Use a parent task with the epic label. Join its child tasks with subtask and parenttask relations. An epic has no work of its own. Nightly sets percent_done from the children and closes the epic when the last child closes. |
| 4 | Order and links. | Use blocking and blocked for hard dependencies; precedes and follows for order; duplicateof for a duplicate, then close the duplicate; related for context. |
| 5 | Flow. | Each domain project has one kanban view with Backlog, Ready, In progress, Blocked, and Done buckets. Triage moves a task to Ready only after rules 1 and 2 pass and no open blocked relation remains. Ready holds at most 10 tasks. A done change moves a task to Done automatically. |
| 6 | Claim. | The session that takes a task assigns its role's bot and moves the task to In progress. Use one assignee. Nightly returns an unchanged claim to Ready after 24 hours and comments on it. |
| 7 | Cycle. | A cycle is one week, Monday through Sunday UTC. A task assigned to the cycle has a due date on its last day. The digest counts tasks set for the cycle, tasks done, and tasks rolled over. On Monday, triage rolls unfinished tasks forward with one comment. |
| 8 | Priority. | Use the native priority field: 5 do now, 4 this cycle, 3 high, 2 medium, and 1 low. Triage never leaves priority 0 in a domain project. |
| 9 | Labels. | Use the declared labels epic, needs-split, needs-info, from-untrusted, and operator-step. The project names the area. Do not use area labels or size labels. |
| 10 | Evidence. | A close comment carries proof: the merged pull request URL or the check's output line. Never delete a task. Reopen through one clerk request. |
| 11 | Recurring work. | Use a native repeating task, not a new task for each run. |
| 12 | Incidents. | Incidents never enter Vikunja. Track them in Zammad. |


## Nightly limits

For each run, nightly closes at most 10 tasks, creates at most 25 relations, and marks at most 10 duplicates.
It does not delete tasks. It acts only on domain-project tasks changed in the last 14 days. Every close cites evidence.
The digest lists each change and the clerk request that undoes it.

## Why it works this way

Vikunja's native fields carry the task workflow. The agent contract
sets the shared caller and tool rules. The agent platform decisions
record the accepted tracker path.
