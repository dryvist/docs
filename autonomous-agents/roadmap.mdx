<Note>
Status: **in progress.** OpenBao and both its secrets engines are live. The Mac
container path is in use. The agent pool is declared in infrastructure code and
its converge role is written, with the first canary run outstanding. Each linked
page carries the current status for its workstream.
</Note>

> Seven phases, each independently shippable, each with a rollback. The boundary
> first, the secrets second, the decommission last.

## Phases

<Steps>
<Step title="Profiles + image + local Mac runs (done)">
The three autonomy profiles landed in nix-ai; the `nix-agent-sandbox` repo
ships `agent-image` and `agent-cli`; `agent run` works via Apple
`container` on the Mac.
</Step>
<Step title="The agent pool in infrastructure code (done)">
A dedicated firewall profile for pooled agent guests covers internal
services plus the forward proxy, with no direct outbound web rule. It
works with the proxy guest that holds the domain allowlist. Both are
declared in tofu-proxmox.
</Step>
<Step title="Pool converge role + canary (role written, canary pending)">
The `agent_guest` role converges a stock Debian LXC into a queue-pulling
agent guest: one systemd unit per job, credentials rendered per job,
transcripts shipped. The canary is one real job per agent command-line
tool on a pool guest. The legacy runtime retires only after it passes.
</Step>
<Step title="OpenBao (AWS STS live)">
Core OpenBao is deployed. AppRole and response-wrapped bootstrap provide the
machine path. The AWS STS engine now brokers AWS access for automation,
replacing the static [aws-vault](/security/tools/aws-vault) base key.
Other static service credentials continue moving into OpenBao KV.
</Step>
<Step title="GitHub App service engine">
A separate OpenBao engine issues fixed, named permission sets as one-hour
installation tokens. Routine automation PATs retire after live issuance,
use, and revocation checks pass.
</Step>
<Step title="Consumer migration">
Agent launchers consume the GitHub engine. Access outside the configured
full-automation ceiling stays human-only; remaining privileged PATs become
break-glass credentials.
</Step>
<Step title="Decommission">
The legacy agent guests and the launcher zsh they needed are removed once
the pool carries load. Routine machine secrets finish moving out of
[Doppler](/security/tools/doppler). An optional credential-injecting
proxy covers static-credential backends.
</Step>
</Steps>

## Repo ownership map

| Repo | Owns | Change |
| --- | --- | --- |
| [nix-claude-code](/nix/nix-claude-code) | Interactive permission data only | No autonomous configs ever rendered here |
| [nix-ai](/nix/nix-ai) | The three profiles + posture-aware formatters | Phase 1 |
| `nix-agent-sandbox` (dryvist) | The Mac path: `agent-image` and `agent-cli` | Phase 1 |
| [tofu-proxmox](/infrastructure/repos/tofu-proxmox) | Pool guests, their firewall profile, the proxy guest | Phase 2 |
| `ansible-proxmox-ai` (dryvist) | The `agent_guest` converge role and the queue worker | Phase 3 |
| [nix-darwin](/nix/nix-darwin) | Installs agent-cli | Launcher zsh deleted in phase 7 |

## Pages this supersedes in part

This section changes the trajectory of several existing pages without rewriting
them yet. Until each phase lands, the existing pages describe the live system.

- [aws-vault](/security/tools/aws-vault): already replaced for automation by
  the OpenBao AWS STS engine (phase 4); that page now documents the broker
  model that replaced it.
- [Doppler](/security/tools/doppler): the four-tier model (see the
  [comparison](/security/comparison)) keeps Doppler as the strict cloud tier
  holding secret-zero and rare human-approved credentials. Routine machine
  secrets still migrate out in phase 7, into OpenBao.
- [OpenBao](/security/tools/openbao): that page predates this design and
  described OpenBao as a cluster-local alternative store; the four-tier model
  assigns OpenBao the single machine-secrets role (dynamic credentials
  included). The two converge in phase 4.
- [SOPS in repos](/security/sops-for-iac): unchanged in role; stays the
  layer for committed deployment config.
